# Stitchfy 2.2.0

## Overview

Stitchfy evolved from an executable website generator into a broader solution-engineering framework, while fully preserving the original website-generation workflow. This release adds a new, additive Solution Architecture pipeline alongside the existing website pipeline: structured business discovery, explainable capability selection, and architecture generation across seven new capabilities, plus two deterministic export adapters and an optional local codebase-analysis tool.

## Existing Website Users

**Nothing changes for you.** Your existing workflow —

```bash
npm run stitchfy
npm run build:site
npm run audit
```

— continues to work exactly as before. You do not need to adopt `npm run solution` or any part of the new architecture pipeline unless you want to. See `docs/releases/UPGRADING_FROM_2_1.md` for the precise compatibility statement.

## New Solution Architecture Pipeline

`npm run solution -- --input <requirements.md>` turns a structured Markdown requirements document into a validated, traceable `SolutionBlueprint`: Business Discovery extracts explicit facts from your document, Solution Planning explains which capabilities apply and why, and each selected capability generates its own architecture.

## New Architecture Capabilities

Each of these **generates or specifies** architecture — none of them run, deploy, or execute anything:

- **Workflow Automation** — generates workflow specifications, including human-in-the-loop approval steps.
- **Integrations** — specifies integration architecture (REST/webhook contracts, authentication, data contracts).
- **AI Agents** — specifies AI agent architecture (tools, permissions, guardrails, memory) tied to real integrations.
- **Security & Governance** — generates security requirements and risk assessments from real workflow/integration/data evidence.
- **Observability** — generates observability architecture (signals, alerts, operational objectives) citing real architecture entities.
- **Cloud / Deployment** — generates vendor-neutral deployment architecture.
- **Legacy Modernization** — generates modernization assessment and migration-strategy architecture.

## Codebase Analysis

`npm run analyze:codebase -- --path <repo>` (standalone) or `npm run solution -- --codebase <repo> --system-id <id>` (integrated) **analyzes** a real Maven/npm/Java repository, read-only and fully offline, and turns it into evidence Legacy Modernization may optionally consume. It never executes code, makes a network call, or extracts secrets.

## Export Adapters

`generic-rest-typescript` and `generic-java-replatform` **propose** reviewable, implementation-oriented scaffolding — generated TypeScript for a complete REST integration, and a migration recipe for an explicitly-approved Java replatform. Both are deterministic and offline; neither applies a change automatically.

## Reference Solutions

Three canonical, end-to-end worked examples (`examples/reference/`) show these capabilities working together on real scenarios, and are regression-tested via `npm run reference:validate`.

## Compatibility

This is the first release with real, documented compatibility guarantees. **STABLE contracts**: `WebsiteBlueprint` v1, `SolutionBlueprint` v1, `npm run stitchfy`, `npm run solution`, `npm run analyze:codebase`. Everything else (export manifests, codebase-analysis output, per-capability JSON, extension APIs) is CANDIDATE or EXPERIMENTAL — real and documented, but not yet a compatibility promise. Full detail: `docs/architecture/PUBLIC_CONTRACTS.md`.

## Deprecated

`SolutionBlueprint.deployment` — never populated by any generator; use `SolutionBlueprint.architecture` instead. Still accepted by validation; only relevant if you're hand-constructing or consuming a `SolutionBlueprint` directly.

## Deferred / Not Included

Explicitly **not** implemented in this release: a live workflow/integration runtime, LLM/model execution, cloud provisioning, observability vendor configuration, and automatic source-code patch generation. All architecture generation is deterministic and offline.

## Upgrade Notes

See `docs/releases/UPGRADING_FROM_2_1.md`. Short version: no migration is required for existing website users; the new pipeline is entirely additive.
